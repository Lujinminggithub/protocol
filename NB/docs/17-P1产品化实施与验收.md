# NB V1.5 P1 产品化实施与验收

## 1. 范围与结论

P1 面向受控试运行到批量开线之间的产品化能力，不改变当前 TCP-over-QUIC 三跳协议，也不启用生产 FEC。固定出口保持不变，动态策略只作用于新会话。

本阶段包含：观测连接退避、租户配额、健康感知选路、middle/exit 多 worker、最小签名控制面、证书重叠轮换。entry 暂时保持单 worker，以保证租户并发和带宽额度是进程级全局精确值；后续若扩展 entry 多 worker，必须先把租户计数迁到共享状态或独立控制面。

## 2. 已实现能力

### 2.1 观测连接

- SSH 建连和外层采集均采用有上限的指数退避与抖动。
- Paramiko 可重试 banner 异常不再直接输出整段堆栈，最终失败仍写入结构化 `collection_errors`。
- 跳板和目标连接生命周期绑定，关闭目标连接时同步释放 entry 跳板。

### 2.2 租户治理

`nb_tenant` 使用 `tenant <用户名> <TCP并发> <UDP并发> <平均Kbps> <累计MB> [峰值窗口秒数]` 配置。
平均速率通过令牌桶长期约束；窗口内可按物理链路能力短时突发，不再设置独立的固定峰值速率。
窗口默认 10 秒，可配置为 1..60 秒；旧的 6 字段配置继续兼容。

- SOCKS 认证成功后把 tenant identity 写入 session，不保存明文密码。
- CONNECT 与 UDP_ASSOCIATE 分别占用并发额度；所有正常、错误和 reset 释放路径统一归还。
- token bucket 按实际读取字节消费，避免短读造成过度限速。
- 总流量、上下行字节、当前并发和拒绝次数由 control socket 的 `tenants` 命令输出。
- 当前 `nbmobile` 基线为 TCP 256、UDP 64、上行聚合 20Mbps、累计流量不封顶。

### 2.3 健康选路

- tenant、目标和端口生成稳定 key，使用加权 rendezvous 为新会话选择 route。
- route 支持容量上限、当前会话数、连续失败、30 秒熔断、成功恢复和拒绝计数。
- 已建立的 TCP/UDP 会话保持粘性，不做中途迁移。
- 所有 route 必须声明与策略相同的 `fixed_exit`；跨出口配置在准备阶段和部署阶段均 fail-closed。
- control socket 的 `routes` 命令输出当前容量、健康和选择统计。

### 2.4 多 worker

- 每个 worker 持有独立 picoquic context，监听 socket 使用 `SO_REUSEPORT`。
- middle 的共享 `:4443` socket只承载上游连接；每个 worker 使用独立临时 UDP 端口建立 middle→exit QUIC 连接，回包按唯一四元组进入正确 context。
- supervisor 对单 worker 使用指数退避重启，crash-loop 达阈值后退出；`SIGHUP` 按 worker 滚动重载，不计入 crash-loop。
- KZ 目标配置为 entry 1 worker、middle 2 worker、exit 2 worker。

### 2.5 控制面与证书

- `nb_p1_control.py` 把 tenant/routes 编译成签名策略工件，校验固定出口、容量和文件哈希后原子下发；entry 滚动重载和主动 payload 失败时恢复上一配置。
- `security_rotate.py` 实现 `prepare -> trust -> identity -> retire` 三阶段证书轮换。
- trust 阶段同时信任新旧 CA；identity 阶段滚动切换节点证书；retire 阶段移除旧 CA并记录旧 CA SHA-256 吊销指纹。
- 阶段顺序、HMAC 签名、远端备份、worker 健康回读和 JSONL 审计均为硬门禁。
