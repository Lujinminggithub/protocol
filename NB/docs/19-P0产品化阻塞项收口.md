# P0 产品化阻塞项收口

更新时间：2026-07-27。

## 已完成并上线

### Entry 进程高可用

- Entry、Middle、Exit 均支持 2 workers，由 supervisor 拉起和恢复。
- Entry 租户并发、速率、配额和累计流量使用 mmap + 文件锁共享，不再按进程重复计算。
- worker lane 端口保证重连仍进入持有目标 TCP fd 的 Exit worker。
- KZ deployment `e1ae894388f00773-d6a324f27ee9` 已按 Exit -> Middle -> Entry 原子部署。
- 三端均回读 2 workers、health=ok，SOCKS 冒烟确认固定 KZ 出口。

这消除了单进程故障。第二台 Entry 尚未提供，因此主机、机房和公网地址单点仍属于已知外部资源限制；数据面代码已经保留多节点扩展边界。

### 逻辑流续传

- NBLS v1 提供 128-bit flow ID、OPEN/DATA/ACK/RESUME/RESUME_ACK、FIN/RST 和有界重放。
- make-before-break 晋升后会主动迁移逻辑流；连接断开后先完成 RESUME_ACK，再从对端确认偏移重放。
- Exit 重绑定会清理旧物理队列，但保留目标 TCP fd 和逻辑流状态。
- 2 MiB 同一 SOCKS/TCP 连接跨全部 Middle workers 强制终止后逐字节一致，集成门禁已通过。

### 用户、计费和运营 API

- Go 只承担运营控制面；C 继续承担延迟敏感的数据面，不在 C event loop 内加入 SQLite/HTTP。
- SQLite 使用 WAL、FULL synchronous、外键和单写连接，保存用户、PBKDF2 凭据、用量事件、游标、账期快照、incident、审计和 durable outbox。
- 用户、凭据、审计和 outbox 在同一事务提交；Idempotency-Key 同请求可重放，不同请求返回冲突。
- 账期关闭 API 冻结每租户上下行字节，迟到事件不会改写已关闭账期。
- 首次启动严格导入现有 C 用户与配额；无配额的旧凭据导入为 disabled，异常时 fail-closed。
- KZ Entry 上的 `nb-control` 已 active/ready，授权 API 验证为 2 active、1 disabled。

### 集中监控与 Web 对接

- 控制面每 15 秒收集 Entry workers 的 health、metrics、tenant 和 route。
- Prometheus 指标带 deployment/line 标签；仓库包含 Grafana 汇总看板和 critical/warning 告警规则。
- provision、usage、snapshot、incident 和 billing 通过带幂等键的 durable outbox 发往既有 Web。
- 支持 Bearer token 和 HMAC-SHA256 签名，失败指数退避，不阻塞数据面。
- 当前未提供 Web base URL/token/signing key，因此 KZ 的事件保留在 SQLite pending outbox；配置后自动投递。

### 大 UDP transport shim

- Xray demo 已支持 1..65507 字节 UDP 数据报，按 NBUD v1 拆为最多 66 个分片。
- 所有分片立即发送，不等待窗口或下一数据报。
- 接收端有界为 8 个乱序重组槽，支持重复分片、超时淘汰、session/type 校验。
- 这是一层可供 Xray outbound 调用的 transport shim；正式手机 TUN/DNS 生命周期仍按决定延期。
