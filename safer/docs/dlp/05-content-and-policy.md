# 05 内容检测引擎与策略模型

> 上级：[README](./README.md) ｜ 相关：[03 异步裁决](./03-async-adjudication.md)、[04 数据通道](./04-data-channels.md)

## A. 内容检测引擎（用户态）

### 现状
`policy_engine.c` 只做元数据匹配（扩展名/URL 子串/域名/HTTP header/JSON 标记），且在内核 DISPATCH 层自旋锁内跑。**这不是内容检测，是元数据匹配**，且层次错位。

### 目标：用户态分层检测引擎
内核抓样本 → 用户态引擎按「由轻到重」分层检测，越靠后越贵，命中即止：

| 层级 | 检测能力 | 说明 | 成本 |
|---|---|---|---|
| L1 | 文件真实类型 | Magic number 识别（非扩展名）| 低 |
| L2 | 关键字/字典 | 敏感词表、多模式匹配（Aho-Corasick）| 低 |
| L3 | 正则模板 | 身份证/银行卡/手机号/密钥/源码特征 | 中 |
| L4 | 数据指纹 | EDM(结构化,如客户表) / IDM(非结构化文档指纹) | 高 |
| L5 | OCR | 图片/截屏文本提取后再走 L2-L4 | 高 |
| L6 | ML 分类 | 文档类别/敏感度模型 | 高 |

- 引擎输出：命中项 + **数据分类等级** + 建议动作，回给策略决策。
- 与内核关系：通过[异步裁决](./03-async-adjudication.md)交互；轻层(L1/L2)结果可回填内核判定缓存。

### 内核侧只保留
- 文件真实类型的快速前缀判断（可选）、扩展名/端口/卷类型等廉价轻判定、判定缓存命中。**重检测一律不入内核。**

## B. 策略模型（分类矩阵）

### 现状
黑名单式：`Blocked扩展名/端口/域名/URL/...` 列表，线性遍历，无分类、无身份维度、无判定缓存、热更新为空实现。

### 目标：四维矩阵
策略 = **数据分类 × 主体 × 通道 × 动作**：

| 维度 | 取值示例 |
|---|---|
| 数据分类 | 公开 / 内部 / 机密 / 绝密（由检测引擎或外部标签得出）|
| 主体 | 用户/SID/AD 组、进程（名+签名+完整性级别）|
| 通道 | 文件 / 网络 / USB / 打印 / 剪贴板 / 截屏 |
| 动作 | 放行 / 阻断 / 加密 / 脱敏 / 水印 / 审批 / 仅告警 / 用户提示 |

- 规则含**优先级**与**例外/白名单**；命中最高优先级生效。
- 示例：`机密级 × 任意进程 × USB写入 → 阻断+告警`；`内部级 × 已签名OA × 网络 → 放行`。

### 身份上下文（当前缺）
- 进程：名 + 镜像签名主体 + 完整性级别（不只 PID）。
- 用户：token SID / AD 组（需 `SeQueryInformationToken`，PASSIVE 级，应缓存，见下）。

### 引擎性能（内核轻判定侧）
- 端口用位图 O(1)；扩展名/域名用（反转）Trie；多模式子串用 Aho-Corasick 单趟扫描。
- `FastVerdictCache` + `PolicyGeneration` 版本号惰性失效。
- 锁改 `EX_PUSH_LOCK`（读多写少）或 RCU 指针交换，避免 DISPATCH 长自旋。
- SID 缓存：随进程条目缓存，进程退出墓碑期回收。
